# 入仓：把 frontend 放进仓库（成员 C）

> 结论先说：**仓库里已经有一个 `frontend/` 目录**（14 个文件，是另一套实现）。
> 你这份 `frontend/` 是 15 个文件、目录结构不同，**直接覆盖会覆盖掉别人已有的页面**。
> 所以下面先给"安全入仓"的做法，再给"确认要替换"的做法，你自己选。

---

## 一、先看清冲突（很重要）

仓库现状（`qunyi-src/--main/frontend/`，14 个文件）：

```
frontend/
├── index.html            serve.py       start.bat
└── assets/
    ├── api.js  app.js  components.js  state.js  styles.css  util.js
    └── views/
        ask.js  events.js  evidence.js  import.js  library.js
```

你的版本（15 个文件）：

```
frontend/
├── index.html            serve.py       start.bat      README.md
└── assets/
    ├── api.js  app.js  util.js  styles.css  message-actions.js
    └── views/
        overview.js  library.js  search.js  detail.js  system.js
    └── tools/smoke_test.py
```

**同名文件 5 个**：`index.html`、`serve.py`、`start.bat`、`assets/api.js`、`assets/app.js`、`assets/util.js`、`assets/styles.css`、`assets/views/library.js`（共 8 个同名）。
如果你的文件覆盖上去，那么原仓库里的 `components.js`、`state.js`、`views/ask.js`、`views/events.js`、`views/evidence.js`、`views/import.js` 会**变成没人引用的孤儿文件**，而新 `index.html` 引用的是 `overview/search/detail/system` 这些原仓库没有的文件——**两边只要混在一起，页面就会白屏**。

所以只有两个正确选项：

- **选项 A（推荐，最安全）**：改用独立目录 `frontend-c/`，两套实现并存，谁也不影响谁。
- **选项 B**：确认要**完全替换**现有前端，那就先把旧的 `frontend/` 整体删掉，再放新的。

---

## 二、选项 A：并存到 `frontend-c/`（推荐）

### 1. 拷贝（在仓库根目录执行）

```cmd
xcopy /E /I "C:\Users\h'p\WorkBuddy\2026-10-26-23-14-25\frontend" frontend-c
```

### 2. 确认只多了新目录

```cmd
git status --short
```
应只看到 `?? frontend-c/`（或 `A  frontend-c/...` 一堆新增），**不应出现任何 `M  frontend/...`**。

### 3. 提交

```cmd
git add frontend-c/
git commit -m "成员C：新增可核验前端实现（frontend-c）" -m "消息库/导入/智能查找/原文详情/系统状态 五页；serve.py 同源代理规避后端无 CORS；tools/smoke_test.py 43 项联调自检。与现有 frontend/ 并存，不改动后者。"
git push
```

### 4. 顺手改一下 README 的启动端口

`frontend-c/README.md` 里的 `python serve.py` 默认端口是 **5173**。如果以后两套同时跑，加个端口即可：

```cmd
python serve.py --port 5174
```

## 三、选项 B：完全替换现有前端

**只有在你和成员 A 确认过、旧 `frontend/` 不要了** 的情况下才能这样做。

```cmd
:: 1) 先备份（不要跳过）
xcopy /E /I frontend frontend-backup

:: 2) 删除旧前端目录（只删 frontend/，绝不删 member-d/）
rmdir /S /Q frontend

:: 3) 放入新前端
xcopy /E /I "C:\Users\h'p\WorkBuddy\2026-10-26-23-14-25\frontend" frontend

:: 4) 肉眼确认目录结构是新的（有 views\overview.js，没有 components.js）
dir frontend\assets\views

:: 5) 提交
git add -A frontend/
git commit -m "成员C：以可核验交互重写前端（含同源代理与 43 项自检）"
git push
```

## 四、不管选哪个，这两条不能错

### 1. 绝对不要提交令牌与运行时数据

仓库 `.gitignore` 里已经有这几行，正常不会误提交，但**手工拖拽上传网页时最容易带上去**：

```
**/state/
**/credentials.json
**/*.sqlite*
**/__pycache__/
**/*.pyc
```

提交前自检一遍，**输出应当是空的**：

```cmd
git status --short | findstr /I "credentials sqlite state/"
```

### 2. 提交前跑一次联调自检（43 项）

```cmd
cd frontend-c
python tools\smoke_test.py --backend-dir ..\member-d\backend
```

看到 `共 43 项：通过 43，失败 0` 再提交。`--backend-dir` 指向真正的后端目录（含 `qunyi/` 包的那个）。

> 自检会自己导入 2 条 `【自检】...` 消息，结束时自动删掉并把索引重建一次，不会污染演示数据。

## 五、如果手上没有 git（用 GitHub 网页上传）

本机 PowerShell 里 `git` 不在 PATH，这种情况最省事的方式是网页上传：

1. 打开仓库 → `Add file` → `Upload files`
2. 把解压出来的 `frontend-c` **整个文件夹**拖进去（不是拖里面的文件）
3. 底部 Commit message 填：`成员C：新增可核验前端实现（frontend-c）`
4. 选 `Commit directly to the main branch`（或按团队约定开 PR）

⚠️ 拖拽上传时**注意不要带** `state/`、`credentials.json`、`*.sqlite3`——GitHub 网页上传**不会**读 `.gitignore`，拖进去就真进仓库了。

## 六、验收：入仓后怎么证明它真的能用

别人 clone 下来后，三步：

```cmd
:: 终端 1
cd member-d\backend
python -m qunyi

:: 终端 2
cd frontend-c
python serve.py

:: 浏览器
http://127.0.0.1:5173
```

第一次进页面要填令牌，在 `member-d\backend\state\credentials.json` 里：

```powershell
Get-Content .\state\credentials.json
```

文件形如 `{"<令牌>":"demo"}`，**key（引号里那一长串）才是令牌**，粘进去即可（只存本机浏览器）。

演示顺序建议：连接 → 概览（导入示例 3 条）→ 智能查找（问"之前那个志愿活动在哪集合"→ 两个候选 → 点"外出志愿服务"→ 得到时间/地点/截止 + 原文引用）→ 详情（悬停字段看原文高亮）→ 修订（提示会话失效）。
