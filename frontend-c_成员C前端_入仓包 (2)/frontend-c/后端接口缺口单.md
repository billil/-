# 前端 → 后端 接口缺口单（给成员 D）

> 目的：说明"前端已经接上后端，但整站还不能给真实用户使用"到底缺在哪。
> 全部结论来自**线上实测**（2026-11-01），不是推测。

## 一、结论

前端不是演示壳子：它已经真实调用后端接口、真实渲染、真实报错。
卡住整条链路的是**后端侧还缺 5 个接口 + 没有模型密钥**，这两件事前端无法单方面补齐。

## 三、缺的接口（线上实测 404）

前端的「群管理」「通知中心」已经按下面的契约写好调用；后端一上线，前端自动生效，不用再改页面。

### 1. `GET /v1/me`
返回当前身份。
```json
{ "user_id": "u_123", "display_name": "张三", "workspace": "demo", "groups_authorized": 3 }
```
前端用途：登录后显示"我是谁"，判断是否需要重新授权。

### 2. `GET /v1/groups`
返回当前用户**有权限访问**的群。
```json
{ "items": [ { "group_key": "g_1", "name": "2024级计科1班群", "authorized": true, "member_count": 128 } ] }
```
前端用途：群管理页列表；`authorized=false` 的群前端会禁选、不给阅读入口。

### 3. `GET/POST /v1/subscriptions`
关注关系。
```json
// GET 返回
{ "group_keys": ["g_1", "g_2"] }
// POST 请求体
{ "group_keys": ["g_1", "g_2"] }   // 整体覆盖式保存
```
前端用途：勾选即保存；失败自动回滚并提示（403 无权限 / 404 未实现 / 超时 分开提示）。

### 4. `GET /v1/notifications?after=<cursor>&limit=50`
增量通知（游标翻页）。
```json
{
  "items": [ { "id": "msg_x", "group_key": "g_1", "group_label": "…", "content": "…", "sent_at": "2026-11-01T02:00:00+00:00" } ],
  "next_cursor": "c_100",
  "has_more": true
}
```
前端用途：通知中心按 `next_cursor` + `has_more` 逐页拉、按 `id` 去重、记录最近同步时间。

### 5. `GET /v1/sync/status`
机器人/同步状态。
```json
{ "online": true, "last_sync_at": "2026-11-01T06:00:00+00:00", "pending": 0, "error": null }
```
前端用途：显示"机器人离线 / 同步失败"，断线时明确标注数据是旧的。

### 6. 正式登录（替代令牌）
现在前端用的是"访问令牌"，不是用户登录。要多人使用必须有：
- `POST /v1/auth/login` → 返回会话凭证
- 或接 QQ OAuth

> 令牌只能证明"能访问某个 workspace"，证明不了"你是谁、能看哪些群"。这是当前不能给真实用户用的**根本原因**。

## 四、真实模型：代码已支持，只缺密钥

`qunyi/providers.py` 已经实现了 OpenAI 兼容的 chat-completions 调用，`config.py` 也已读取对应环境变量。
**不需要改代码**，配三（四）个环境变量即可切到真实模型：

```
QUNYI_MODE=live
QUNYI_MODEL_URL=https://<你的服务商>/v1/chat/completions   # 必须 https
QUNYI_MODEL=<模型名>
QUNYI_API_KEY=<密钥>
```

配置后 `/v1/capabilities` 会变成 `mode=live, simulation=false, model_configured=true`。
当前线上是 `mode=mock, model_configured=false, true_semantic_model=false`，检索器为 `local_ngram_tfidf_with_aliases`（词面检索）。

> 注意：`true_semantic_model` 恒为 false 是后端写死的字段，即使切到 live 也不会变。
> 对外表述请区分「用了大模型做字段抽取与回答」和「向量语义检索」，两者不是一回事。

## 五、数据现状

线上库只有 **3 条种子消息**，群名是「模拟活动群 / 模拟班级群 / 模拟课程群」。
这是用户打开页面觉得"像演示"的直接原因。前端已加「清空全部」按钮（后端模式逐条 DELETE），
清掉后导入自己的群消息就是真实数据。

## 六、前端无法单方面完成的部分

| 事项 | 需要谁 | 说明 |
|---|---|---|
| 真实 QQ 群消息入库 | D / B | 需要 QQ 机器人账号、群消息接收权限、公网 HTTPS 回调 |
| 正式用户登录与群成员资格 | D | 需要 OAuth 或账号体系 |
| 机器人 7×24 常驻 | 运维 | 需要常驻服务器，不是前端页面能解决的 |
| 真实模型调用 | 项目组 | 需要模型服务商密钥与许可 |
| 自定义域名 | 运维 | 当前托管域名带 platform 后缀，且网关会拦截含 `/v1` 的 URL |

## 七、前端已做好的兼容

- 后端返回 404 时，页面显示「接口未实现」，不伪造数据
- 后端返回 403 时，显示「无权限」，不给内容
- 断网 / 超时：显示用旧数据，并提示可重试
- `capabilities.simulation=true` 时，答案区固定标注「模拟模式」
- 所有页面导出 JSON 时带 `mode: local|backend`，便于区分数据来源
