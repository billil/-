# 通知同步原型 v2

本版本仍基于工作空间授权，不能代替真实网站用户或群成员权限，不应作为多用户生产权限系统。

## 新增能力

数据库启动时自动创建 `notification_changes` 与增删改触发器，并对现存消息进行一次回填（schema_version 2）。每个变更有单调递增序号。通知接口继续使用 `after`，新游标格式为 `n1:<序号>`，按序分页；`items` 维持消息字段并增加 `change_type`、`change_seq`、`changed_at`。消息删除或迁出群时返回仅含消息 ID、群和变更信息的占位，不包含已删除原文。修改前的事件反映查询时当前消息内容，不提供历史快照。事件回填只覆盖升级时仍存在的消息。

不再接受旧时间戳游标：返回 400 / INVALID_CURSOR，客户端应清除旧游标并完整重同步，可能看到重复消息，应按消息 ID 和 change_seq 去重。这个变更需前端协调，升级前须备份数据库。消息推送属于至少一次语义，客户端不可将 cursor 作为认证凭据。取消关注再重新关注时客户端应清除游标以重新同步；后端当前仍是空间级订阅，尚无个人已读位置。

仅返回已启用且群授权标记有效的订阅；新导入同群消息不会自动撤销已有禁用标记。该标记不是群成员验证，也不限制消息详情和搜索；正式多用户权限仍未实现。机器人在线状态返回 connected=null 和 connection_status=unknown，因为后端还没有真实心跳。该结构变更需要前端处理 unknown，不能当作离线或在线。

## 备份、升级、回滚

在维护窗口先使用 SQLite 备份接口（不要直接复制正在写入的数据库文件）备份，并演练在隔离路径恢复；部署代码前保存旧版本代码和数据库备份。新代码首次启动执行迁移；回退时停服务并恢复升级前备份及旧代码。升级后新增数据不会自动合并到旧备份，因此回滚前须评估并单独保存后续数据。不要对真实数据执行破坏性试验。

## 尚未完成

群用户授权和撤销、B 模块接入、真实模型、机器人多群和状态心跳、用户级已读、消息附件和平台撤回、网关白名单、浏览器联调及生产运维均需另行完成。变更表增长和数据保留策略需后续设计。现阶段测试使用模拟数据，不代表真实 AI 或 QQ 平台全部能力。
