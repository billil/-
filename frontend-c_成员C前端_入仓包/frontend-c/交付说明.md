# 交付说明 · frontend-c（成员 C 前端）

> 本压缩包只包含**要入仓的那 18 个文件**，解压后是一个 `frontend-c/` 目录。
> 令牌、数据库、截图、验证脚本都不在里面。

## 一、怎么用这个包

**方式 A（推荐，git 命令行）**

```cmd
:: 解压到仓库根目录（与 member-d/ 同级），确认出现 frontend-c\
git status --short          :: 应只看到 ?? frontend-c/
git add frontend-c/
git commit -m "成员C：新增可核验前端实现（frontend-c）" -m "六页 + 系统状态；serve.py 同源代理规避后端无 CORS；可选接口探测式接入（404 自动降级）；45 项联调自检。与现有 frontend/ 并存。"
git push
```

**方式 B（GitHub 网页上传）**

1. 仓库 → `Add file` → `Upload files`
2. 把解压出来的 **`frontend-c` 整个文件夹**拖进去（不是拖里面的单个文件）
3. Commit message 填 `成员C：新增可核验前端实现（frontend-c）`
4. ⚠️ 网页上传不读 `.gitignore`，拖拽前确认文件夹里没有 `state/`、`credentials.json`、`*.sqlite3`

**不要**把它解压后覆盖到仓库现有的 `frontend/` 里 —— 两边有 8 个同名文件，
混在一起会白屏（旧的 `components.js` 等变孤儿，新的 `index.html` 引用不存在的页面）。
详见包内 `frontend-c/入仓说明.md`。

## 二、跑起来（验收用）

```cmd
:: 终端 1：后端
cd member-d\backend
python -m qunyi

:: 终端 2：前端
cd frontend-c
python serve.py            :: 或双击 start.bat
```

浏览器打开 <http://127.0.0.1:5173>，第一次要填令牌：
`member-d\backend\state\credentials.json` 的内容是 `{"<令牌>":"demo"}`，
**key（引号里那串）才是令牌**，粘贴即可（默认只存 sessionStorage）。

提交前跑一次自检：

```cmd
cd frontend-c
python tools\smoke_test.py --backend-dir ..\member-d\backend
```

看到 `共 45 项：通过 45，失败 0` 即通过。末尾的「可选接口可用性报告」
（`/v1/me`、`/v1/groups`、`/v1/subscriptions`、`/v1/notifications`、`/v1/sync/status`）
当前全是 404，属预期，不计失败。

## 三、包里有什么

| 路径 | 说明 |
|---|---|
| `frontend-c/index.html` | 外壳：侧边栏（≤900px 折叠为抽屉）+ 顶栏 + 视图容器 |
| `frontend-c/serve.py` | **核心**：静态服务 + `/api` 同源反代（后端无 CORS，没它必跨域失败） |
| `frontend-c/start.bat` | Windows 一键启动 |
| `frontend-c/README.md` | 启动方式、页面-接口对照、边界声明 |
| `frontend-c/入仓说明.md` | 入仓操作手册 + 冲突分析 |
| `frontend-c/assets/styles.css` | 设计系统（浅色，无外部字体，含响应式断点） |
| `frontend-c/assets/api.js` | API 客户端、错误码解释、可选接口探测 |
| `frontend-c/assets/app.js` | 路由、连接配置、移动端抽屉导航 |
| `frontend-c/assets/util.js` | 转义、引用高亮、时间格式化、Toast、对话框 |
| `frontend-c/assets/message-actions.js` | 导入 / 修订 / 删除 / 详情抽屉 |
| `frontend-c/assets/views/overview.js` | 概览 |
| `frontend-c/assets/views/library.js` | 消息库 |
| `frontend-c/assets/views/search.js` | 智能查找（五种 query 状态） |
| `frontend-c/assets/views/detail.js` | 原文详情（字段悬停 → 原文定位） |

| `frontend-c/tools/smoke_test.py` | 45 项联调自检（无需浏览器） |

## 四、能力边界（对外别说过头）

- 后端 `mock` 模式是确定性规则，**不理解任意口语更正**。
- 检索是本地 n-gram / TF-IDF，**不是向量语义检索**。
- 群管理、通知中心是「探测 + 降级」实现：后端还没 `/v1/groups`、`/v1/subscriptions`、
  `/v1/notifications` 时，页面显示「待后端实现（404）」并用已有能力做等价视图；
  通知中心的本地轮询**不是服务端推送**，已读只存本机。接口上线后前端零改动自动切换。
- 未做生产部署：无 HTTPS / 登录 / 限流，`serve.py` 仅供本机联调。
